# misra - Agent Guide

Canonical instructions for AI coding agents. `CLAUDE.md` and `GEMINI.md` point here; edit this file only.

## Project

Daily batch pipeline that crawls career pages, keeps history in SQLite, and emails a digest. Runs on GitHub Actions; there is no server or API. The only UI is the static dashboard in `docs/`.

## Commands

- Install: `npm ci`, then `python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'`
- Lint: `npm run lint` (ruff, ESLint, Stylelint, html-validate, markdownlint)
- Typecheck: `npm run typecheck` (mypy, strict)
- Test: `npm run test`
- Coverage: `npm run test:coverage` (pytest, 100% line and branch coverage; mandatory on push and in CI)
- Run the pipeline: `.venv/bin/python run.py`, then `.venv/bin/python send_email.py` and `.venv/bin/python build_dashboard.py` (see README)

## Rules

- Never commit with `--no-verify`. Fix the cause when a hook fails.
- This repository uses GitHub issues for ticketing.
- Linters are strict (ruff, mypy, ESLint, Stylelint, html-validate, markdownlint). Do not weaken rules to pass.
- The files in `docs/` (`index.html`, `dashboard.css`, `dashboard.js`, `theme.js`, `jobs.json`, `jobs.jsonld`) are generated by `build_dashboard.py` from `templates/dashboard.html`, `templates/dashboard.js`, `templates/theme.js` and the data: edit the templates, never the output. `docs/dashboard.css` bundles `design-system/tokens.css`, `design-system/components/*.css` and `templates/dashboard.css`. The page has no inline script or style (its Content-Security-Policy forbids them); add integrity hashes through the `__SRI_*__` placeholders in the template.
- UI work follows `design-system/README.md`: tokens only (no raw colors outside `tokens.css`), kebab-case classes, light and dark, WCAG AA, 44px targets. Keep the dashboard agent-readable: `data-*` hooks on `article.card`, the JSON-LD in `jobs.jsonld`, and the WebMCP tools registered in `templates/dashboard.js`.
- Python lives at the repository root (flat modules). Node is dev tooling only (linters, hooks, release gate); pin it via `.nvmrc`, package manager is `npm`. Keep `package-lock.json` committed.
- Keep the version in `package.json` and `pyproject.toml` equal. PRs that change `package.json`, `pyproject.toml`, or a listed Python module update `CHANGELOG.md` and bump both (one SemVer bump per PR). Docs-only, test-only, and workflow-only PRs do not.
- When adding a Python module, add it to `RELEASE_TRIGGER_PATHS` in `.github/workflows/ci.yml` and `.husky/pre-push`, and to `py-modules` and mypy `files` in `pyproject.toml`; the release gate only watches that list.
- The daily workflow commits `data/jobs.db` and the built `docs/` files straight to `main`. It pushes with the `DEPLOY_KEY` secret (a write deploy key), written to disk only in the final push step by `scripts/deploy-key.sh`, never during the crawl; do not add `ssh-key:` to the checkout step. That key is the only actor allowed to push directly to `main` under the `protect-main` ruleset (the Actions bot cannot be a bypass actor on a personal repo). Do not change that flow without updating the ruleset.

## Layout

- Python modules at the root (`run.py`, `adapters.py`, `browser_crawl.py`, `digest.py`, `classify.py`, `regions.py`, `send_email.py`, `build_dashboard.py`, `discover.py`, `common.py`, dev tools `survey*.py`), `tests/` for pytest
- `data/` - seed lists and the SQLite history; `templates/` - dashboard page, script and styles; `docs/` - generated dashboard (GitHub Pages)
- `design-system/` - tokens, components, showcase page (`index.html`), logo brief; `templates/dashboard.css` - dashboard layout
- `.husky/` - git hooks (pre-commit fast, pre-push broad)
- `.github/` - CI, release, daily pipeline, dependabot, templates
