Design system

Scan fast. Decide faster.

Misra is a daily drop of entry-level and student roles in Israel. People open it on a phone, thumb through, apply or move on. Big type, one action per card, loud only about what is new. Light and dark. Plain HTML and CSS.

Color

Cream and ink carry the layout. Violet means act, lime means new, amber means be careful. Every token has a light and a dark value in tokens.css.

Type and shape

System UI stack, heavy weights, tight tracking, no webfont. Radii 14, 20 and pill. 2px borders and hard offset shadows, never blur. Targets are at least 44px.

Built for agents too

The page a person scans is one an agent can read and drive. Cards are article elements with data-job-id, data-company, data-level, data-role-types, data-regions, data-new, data-stale, data-discarded and data-starred. Every open role is in a schema.org JobPosting JSON-LD block. The dashboard registers these WebMCP tools on navigator.modelContext when the browser offers it:

  • search_jobs(query, levels, roleTypes, regions, includeRemoteNotSaid, company, newOnly, includeDiscarded, sort, limit)
  • list_filters()
  • list_new_jobs(limit)
  • get_job(id)
  • star_job(id), unstar_job(id), list_starred_jobs()
  • discard_job(id), restore_job(id)
  • get_sync_status(), import_browser_choices(filters)
  • list_coverage_gaps()

There is deliberately no tool that deletes an account: that needs a person to read the warning and confirm.
